# API Specification and Postman Collection

This directory contains the connection contract for the current FastAPI backend on the repository `main` branch.

## Deliverables

- `openapi.json`: OpenAPI 3.1 specification exported from `Backend/app/main.py`, with local server metadata and documented runtime authentication errors.
- `Nhom5_API.postman_collection.json`: Postman Collection v2.1 for health, authentication, RBAC, and basic negative tests.
- `Nhom5_Local.postman_environment.json`: local environment variables for the collection.

## Current endpoints

### System

- `GET /health`

### Authentication

- `POST /api/v1/auth/register`
- `POST /api/v1/auth/login`
- `POST /api/v1/auth/refresh`
- `GET /api/v1/auth/me`
- `POST /api/v1/auth/logout`

### RBAC

- `GET /api/v1/rbac/admin`
- `GET /api/v1/rbac/teacher`
- `GET /api/v1/rbac/student`
- `GET /api/v1/rbac/parent`

`ADMIN` can access every RBAC endpoint. `TEACHER`, `STUDENT`, and `PARENT` can access only their matching endpoint.

## Run the backend

From the `Backend` directory:

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate

# Linux/macOS
source .venv/bin/activate

pip install -r requirements.txt
uvicorn app.main:app --reload
```

The backend expects PostgreSQL and reads configuration from `.env`. The default local URL is `http://localhost:8000`.

After startup:

- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`
- Runtime OpenAPI: `http://localhost:8000/openapi.json`

## Import into Postman

1. Open Postman and select **Import**.
2. Import `Nhom5_API.postman_collection.json`.
3. Import `Nhom5_Local.postman_environment.json`.
4. Select the **Nhom 5 - Local** environment.
5. Update `login_email` and `password` to match an existing database user.
6. Run **System / Health Check**.
7. Run **Authentication / Login**. Its test script automatically stores `access_token` and `refresh_token`.
8. Run **Get Current User**, **Refresh Token**, or the appropriate RBAC request.

The logout request removes both tokens from the Postman environment after the server acknowledges logout. The backend uses stateless JWTs, so logout does not revoke an already issued token on the server.

## Expected status codes

- `200`: successful login, refresh, current-user lookup, logout, or RBAC access.
- `201`: successful registration.
- `401`: missing, invalid, expired, or wrong token type; invalid login credentials.
- `403`: inactive account or insufficient role.
- `409`: duplicate registration email.
- `422`: invalid request body generated by FastAPI validation.

## Scope note

This specification documents only endpoints implemented in the current repository. Placeholder frontend pages such as assessment, roadmap, practice, AI tutor, and analytics do not yet have backend endpoints and are intentionally excluded.
